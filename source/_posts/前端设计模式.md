# 前端设计模式

## 三种类型

创建型：这类模式关注对象的创建方式，通过封装创建逻辑来简化复杂对象的生成。

结构型（组合型）：这类模式关注如何组合对象和类，形成更高效的结构。

行为型：这类模式关注对象之间的交互和职责分配。

### 创建型

#### 单例模式

定义： 确保一个类只有一个实例，并提供全局访问点。

应用场景： 全局状态管理（Redux/Vuex的Store管理）、浏览器缓存管理（localStorage）、日志工具类。

##### vuex怎么实现的单例模式(vue2)

插件使用时检查

```javascript
// Vuex 源码中的 install 方法（简化版）
function install (_Vue) {
  if (Vue && _Vue === Vue) {
    console.error('[vuex] already installed. Vue.use(Vuex) should be called only once.');
    return;
  }
  Vue = _Vue;
  applyMixin(Vue); // 将 store 注入到 Vue 的实例中
}
// 确保 Vue.use(Vuex) 只能被调用一次，防止重复注册 Store 插件。
```

store的唯一实例化

```javascript
// 在创建 new Vuex.Store(options) 时，Vuex 会生成一个唯一的 Store 实例，并通过 Vue 的响应式系统将其绑定到组件中。
// 创建 Store 实例
const store = new Vuex.Store({
  state: { count: 0 },
  mutations: {
    increment(state) {
      state.count++;
    }
  }
});
```

全局唯一访问点

```javascript
// Vuex 源码中的 applyMixin（简化版）
// Vuex 通过 Vue 的 mixin 机制，将 Store 实例挂载到所有组件的 this 上，提供统一的访问入口。
function applyMixin(Vue) {
  Vue.mixin({
    beforeCreate() {
      if (this.$options.store) {
        this.$store = this.$options.store; // 将 Store 实例挂载到根组件
      } else {
        this.$store = this.$parent && this.$parent.$store; // 子组件继承父组件的 $store
      }
    }
  });
}
```

##### vuex怎么实现的单例模式(vue3)

*   使用 Vue 3 的 **reactive()** 创建响应式状态对象
*   使用 **provide()** 和 **inject()** API 将 store 提供给所有组件
*   所有组件通过注入获取的是**同一个 store 实例**
*   状态变更通过 mutations 和 actions 进行，确保可追踪

```javascript
// 在根组件全局注入store
app.provide('store', this)

// 在useStore内获取实例
const store = inject('store');
```

#### 工厂模式

定义：通过工厂函数/类封装对象的创建逻辑，隐藏具体类的实例化过程。

应用场景：动态创建组件（如React的`createElement`）、第三方库封装（如JQuery的`$()`）

#### 原型模式

定义：通过复制现有对象（原型）来创建新对象。

应用场景：克隆复杂对象（如表单配置）、避免重复初始化开销。

### 结构型（组合型）

#### 装饰器模式

定义： 动态扩展对象功能、不修改原对象

应用场景：组件功能增强（如为按钮添加权限校验）、React高阶组件（HOC）

#### 代理模式

定义： 通过代理对象控制对原对象的访问

应用场景：数据响应式（Vue3的`proxy`）(跳转另一篇）、图片懒加载、Api拦截请求（守卫）

#### 适配器模式

定义： 将不兼容的接口转换为兼容的接口，使不同对象协同工作。

应用场景： 统一数据格式、兼容旧代码、跨浏览器事件封装（react的合成事件）。

#### 外观模式

定义： 为子系统提供简化的统一接口

应用场景： 封装复杂库（如JQuery）、简化Dom操作。

### 行为型

#### 观察者模式

定义： 对象间一对多依赖，状态变化自动通知观察者。

应用场景： 表单联动校验、Dom事件监听（addEventListener）

#### 发布-订阅模式

定义： 通过事件中心解耦发布者与订阅者

应用场景：组件通信（Vue的eventBus）、websocket消息广播

#### 策略模式

定义： 封装算法族，使其可动态替换。

应用场景：表单校验（不同规则对应不同策略）、条件渲染优化。

#### 中介者

定义： 通过中介者协调多个对象间的交互，减少直接依赖。

应用场景：复杂组件通信（如聊天室消息管理）、状态同步。

#### 访问者模式

定义：将操作与数据结构分离，允许新增操作而不修改数据类。

应用场景：复杂对象结构的遍历（如AST解析）。
