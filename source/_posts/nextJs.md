# NextJs

*   完善的工程化机制: 通过脚手架搭建项目, 该有的配置都给你弄好, 同时还支持扩展配置

*   基于文件、目录的路由系统, 支持动态路由、路由分组、平行路由、路由拦截等特性

*   基于 NodeJS 可配置中间件, 对用户访问的页面进行重定向、鉴权等操作

*   基于 NodeJS 可以编写简单的 API 接口

*   支持服务端组件、客户端组件, 服务端组件可直接调用 NodeJS 相关 API、可直接访问数据库

*   支持各种渲染方式

*   CSR(Client-side Rendering): 客户端渲染, 简单理解就是正常的 React 项目, 页面的渲染是由浏览器端通过 JS 渲染出来的

*   SSR(Server-side Rendering): 服务端渲染, 每次用户访问路由, 在服务端直接通过 NodeJS 对页面进行渲染, 渲染成完整的页面后返回给用户, 从而提高页面访问速度和 SEO, 因为是服务端生成的页面, 所以你可以轻松访问数据、调用接口(速度更快)、或者直接调用 NodeJS API 访问服务端本地文件资源...

**除此之外还有很多其他特殊作用的页面, 比如: template.js、not-found.js、error.tsx、loading.tsx、not-find、route.js、middleware.js。**

### 文件系统路由算法

Next.js 的文件系统路由是一种基于文件和目录结构自动生成路由的机制。 这种设计使得开发者可以通过创建文件和目录来定义应用的路由结构，而无需手动配置路由。

原理：

*   **约定优于配置**：Next.js 使用特定的文件名和目录结构约定来自动生成路由，减少了手动配置的需要。
*   **编译时静态分析**：在构建时，Next.js 会扫描 app 目录，分析文件结构，并生成相应的路由配置。
*   **基于 React Server Components**：默认情况下，路由页面都是服务器组件，这有助于提升性能。
*   **增量采用**：支持与传统的基于客户端的路由库共存，方便现有项目迁移。

路由匹配算法：

1.  首先尝试精确匹配（exact match）
2.  如果没有精确匹配，尝试动态路由匹配（如 \[id]）
3.  如果还是没有匹配，尝试捕获所有路由（如 \[...slug]）
4.  最后，如果都没有匹配，渲染 404 页面

### 服务器端渲染

服务器端渲染（SSR）是指在服务器上生成HTML内容，然后将完整的HTML页面发送给客户端的过程。 Next.js 提供了强大的服务器端渲染能力，使页面能够在服务器上预渲染，提升首屏加载速度和SEO表现。

在数据没有返回的时候会先采用suspense组件的fallback

Next.js 服务器端渲染的核心原理包括：

*   **请求处理流程**：当用户访问一个页面时，Next.js 服务器接收请求，执行页面组件， 获取数据，生成HTML，然后将完整的HTML响应发送给客户端。
*   **React Server Components**：Next.js 13+ 引入的服务器组件允许组件直接在服务器上执行， 无需在客户端JavaScript中包含这些组件的代码。
*   **水合（Hydration）过程**：客户端接收HTML后，React会将静态HTML与JavaScript逻辑关联起来， 使页面变得可交互。
*   **数据获取方法**：支持多种数据获取方法，如 getServerSideProps（传统SSR）和 服务器组件中的异步数据获取（新架构）。

| 服务器端渲染优势                | 客户端渲染优势       |
| :---------------------- | :------------ |
| - 更快的首屏渲染               | - 更快的页面切换体验   |
| - 更好的SEO                | - 更丰富的交互体验    |
| - 更低的客户端资源消耗            | - 减少服务器负载     |
| - 更好的首内容指标（FCP）         | - 更好的离线支持     |
| - 支持禁止javascript的浏览器（？） | - 适合动态变化频繁的应用 |

SSR最佳实践：

1.  **合理使用服务器组件**：将数据获取、重型计算、访问后端资源的逻辑放在服务器组件中。
2.  **优化水合过程**：最小化客户端JavaScript体积，使用`use client`指令只在必要时启用客户端功能。
3.  **缓存策略**：对频繁访问但不经常变化的数据实施缓存，减少服务器负载。（？）
4.  **错误处理**：实现优雅的错误边界和加载状态，提升用户体验。
5.  **性能监控**：使用Next.js的分析工具监控和优化服务器渲染性能。

### 静态站点生成（SSG）

静态站点生成（SSG）是Next.js的一种渲染方式，它在构建时预渲染所有页面为静态HTML文件。 这些静态页面可以被**CDN缓存**，提供极致的**加载性能**和**SEO表现**。

###### 底层原理

Next.js 静态站点生成的核心原理包括：

*   **构建时预渲染**：在应用构建阶段，Next.js会预渲染所有标记为静态的页面， 生成对应的HTML、CSS和JavaScript文件。
*   **数据获取方法**：传统上使用`getStaticProps`在构建时获取数据， 新架构中则直接在服务器组件中使用异步函数获取数据。
*   **静态资产优化**：自动优化和压缩静态资源，包括图像、CSS和JavaScript。
*   **CDN集成**：生成的静态文件可以轻松部署到CDN，实现全球内容分发。

SSG跟SSR对比

| 特性    | 静态站点生成 (SSG) | 服务器端渲染 (SSR) |
| :---- | :----------- | :----------- |
| 渲染时间  | 构建时          | 每个请求时        |
| 性能    | 极高 (CDN缓存)   | 良好           |
| 服务器负载 | 极低           | 中等至高         |
| 内容新鲜度 | 需要重新构建       | 每个请求都是最新的    |
| 适用场景  | 内容变化不频繁的页面   | 内容频繁变化的页面    |

实践：&#x20;

*   合理划分静态和动态内容：将不常变化的内容预渲染为静态页面，将动态内容通过客户端数据获取或增量静态再生处理。
*   利用增量静态再生：使用ISR技术可以在保持静态页面性能的同时，定期更新内容，无需重新构建整个站点。
*   优化构建时间：对于大型站点，使用动态导入、代码分割和增量构建来优化构建过程。
*   结合CDN使用：将生成的静态资源部署到CDN，实现全球内容分发，进一步提升加载速度。

### 动态路由

动态路由允许你创建能够匹配不同URL模式的页面，这些URL模式可以包含可变部分（称为路由参数）。 在Next.js中，你可以通过在文件或目录名中使用方括号（如\[param]）来创建动态路由。

    // 文件结构
    src/app/blog/[id]/page.tsx
    src/app/products/[slug]/page.tsx
    src/app/users/[userId]/settings/page.tsx

    // 获取路由参数
    export default function PostPage({ params }) {
      const { id } = params;
      return {
        <h1>Post }{id}{</h1>
      }
    }

Next.js 动态路由的核心原理包括：

*   **文件系统路由约定**：Next.js使用文件系统作为路由API，通过特定的文件命名约定来定义动态路由。 在App Router中，动态路由参数使用方括号语法，如`[id]`或`[slug]`。
*   **路由匹配算法**：Next.js在构建时分析文件系统结构，为每个动态路由生成对应的路由匹配模式。 当用户访问一个URL时，Next.js会根据这些模式找到匹配的页面组件。
*   **参数传递机制**：匹配到动态路由后，Next.js会提取URL中的参数值， 并通过`params`对象传递给页面组件。
*   **可选路由和通配符**：Next.js支持可选路由参数（使用双括号`[[param]]`）和通配符路由（使用`[...slug]`）， 提供更大的灵活性来匹配各种URL模式。
*   **动态参数类型**：路由参数在URL中是字符串形式，但Next.js提供了API允许你验证和转换参数类型。

### API路由

Next.js API路由允许你在Next.js应用程序中创建API端点，无需单独设置后端服务器。 这些API端点可以处理各种HTTP请求（如GET、POST、PUT、DELETE等），并直接与数据库、第三方服务交互， 或执行服务器端逻辑。

```javascript
// API路由处理函数示例
// src/app/api/users/route.ts
import { NextResponse } from 'next/server';
export async function GET() {
  // 获取数据逻辑
  const users = [/* 用户数据 */];
  return NextResponse.json({
    data: users,
    message: '获取成功'
  });
}
export async function POST(request: Request) {
  const body = await request.json();
  // 创建用户逻辑
  return NextResponse.json({
    data: body,
    message: '创建成功'
  });
}

/**
src/app/api/
  users/
    route.ts
  products/
    [id]/
      route.ts
    route.ts
  settings/
    route.ts
*/
```

Next.js API路由的核心原理包括：

*   **文件系统路由**：与页面路由类似，Next.js使用文件系统来定义API路由。 在App Router中，API路由文件通常位于`app/api`目录下，并命名为`route.ts`。
*   **请求处理函数**：API路由文件通过导出命名的异步函数（如`GET`、`POST`、`PUT`、`DELETE`等） 来处理不同的HTTP请求方法。
*   **动态API路由**：与页面路由类似，API路由也支持动态参数，使用方括号语法（如`[id]`）。
*   **服务器环境**：API路由在服务器端执行，有权访问服务器资源、环境变量和后端服务。
*   **请求与响应对象**：Next.js提供了增强的Request和Response对象，包括`cookies`、`headers`等方法， 便于处理请求和构建响应。
*   **中间件支持**：Next.js API路由可以与中间件结合使用，实现认证、日志记录、CORS处理等横切关注点。

### 图像优化

Next.js 图像优化是一项内置功能，它可以自动优化网站中的图像，包括调整大小、转换格式、提供响应式图像和延迟加载等。 这些优化可以显著提高页面加载速度，改善用户体验和SEO表现。

Next.js 图像优化的核心原理包括：

*   **内置图像处理器**：Next.js内置了一个图像处理器，它可以在构建时或请求时动态处理图像。 这个处理器能够调整图像大小、转换格式和应用其他优化。
*   **按需调整大小**：Next.js不会提供原始大小的图像，而是根据用户设备的视口大小， 动态生成并提供最合适大小的图像，减少不必要的数据传输。
*   **格式自动转换**：Next.js会根据浏览器支持情况，自动将图像转换为最适合的格式， 如WebP、AVIF等现代格式，这些格式通常比传统的JPEG和PNG提供更好的压缩率。
*   **响应式图像生成**：Next.js会自动为不同屏幕尺寸生成多种分辨率的图像版本， 并使用适当的HTML标记（如srcset和sizes）确保浏览器加载最合适的版本。
*   **延迟加载**：默认情况下，Next.js的图像组件会实现延迟加载，只有当图像进入视口时才会加载， 减少初始页面加载时间和带宽消耗。
*   **缓存策略**：优化后的图像会被缓存，无论是在CDN还是浏览器中，进一步提高了后续访问的性能。

图像通常是网页中最大的资源，优化图像可以显著提高页面加载速度：

*   **减少文件大小**：通过压缩和格式优化，通常可以减少60-80%的图像大小
*   **提高加载速度**：更小的文件大小意味着更快的加载时间，特别是在移动设备上
*   **降低带宽消耗**：优化的图像可以为用户和网站所有者节省带宽成本
*   **改善用户体验**：更快的页面加载速度会提高用户满意度和参与度
*   **提升SEO排名**：页面加载速度是搜索引擎排名的重要因素
